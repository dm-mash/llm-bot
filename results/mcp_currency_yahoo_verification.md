## Требования ТЗ → реализация

| Требование | Реализация | Проверка |
|---|---|---|
| Несколько MCP-инструментов | сервер `currency_yahoo` ([`llm_bot/mcp_servers/currency_yahoo.py`](../llm_bot/mcp_servers/currency_yahoo.py)): `fetch_rates`, `analyze_rates`, `save_report`, `save_series` | e2e: каталог и схемы в реальном stdio-процессе |
| Инструмент 1 — получить данные | `fetch_rates`: суточный курс USD/EUR/GBP к RUB из Yahoo Finance chart API (`RUB=X`/`EURRUB=X`/`GBPRUB=X`, без ключа); длинные периоды прореживаются до ~24 точек (первая и последняя сохраняются) | unit: парсер ответа (пропуск null-закрытий, сортировка), прореживание с сохранением концов |
| Инструмент 2 — обработать | `analyze_rates`: период, старт/конец, min/max, среднее, abs/% изменение, тренд; принимает строку JSON / dict / список точек | unit: точные агрегаты на фикстуре (mean 100.625, +2.5 %, рост) |
| Инструмент 3 — сохранить отчёт | `save_report`: JSON-хранилище `CURRENCY_REPORTS_DB` (по умолчанию `data/currency_reports.json`), атомарная запись tmp+rename + `flock`, идемпотентность по хешу содержимого | unit: повторная запись не создаёт дубликат |
| Выгрузка ряда в файл **без анализа** | `save_series`: пишет сырой ряд из `fetch_rates` в JSON-файл (`CURRENCY_SERIES_DIR`, по умолчанию `data/currency_series`); имя = валюта+период → повторная выгрузка перезаписывает тот же файл | unit (4 сценария) + e2e частичной цепочки fetch → save_series |
| **Агент сам строит цепочку из одного промпта** | контракт данных в первой строке docstring (что принимает, что возвращает, куда передать результат) — **без нумерации шагов**; инструкции роутера «строй ЦЕПОЧКУ… ПО ОДНОМУ»; цикл агента со служебными ответами | scripted: полный fetch → analyze → save **и** частичный fetch → save_series |
| Данные корректно передаются между тула́ми | сырой текстовый вывод предыдущего инструмента передаётся в аргументы следующего — строкой JSON **или готовым объектом** | e2e-цепочка по stdio + scripted-тесты на байт-в-байт передачу |

## Архитектура

- **бэкенд** [`llm_bot/api/currency_yahoo.py`](../llm_bot/api/currency_yahoo.py) —
  вся логика без MCP: `fetch_rates` (Yahoo + fixture-режим для офлайна),
  `_downsample`, `analyze_rates`, `save_report`, `save_series`; доменные
  ошибки `CurrencyError` / `DuplicateReportError` (несёт существующий отчёт).
- **MCP-сервер** [`llm_bot/mcp_servers/currency_yahoo.py`](../llm_bot/mcp_servers/currency_yahoo.py)
  — FastMCP stdio, четыре инструмента, имя сервера и ключ конфига —
  `currency_yahoo` (в пространстве имён инструментов: `currency_yahoo__fetch_rates`).
- **инструкции о цепочках** в [`render_tools_block`](../llm_bot/mcp_tools.py):
  «Для сложной задачи строй ЦЕПОЧКУ вызовов… Выполняй их ПО ОДНОМУ: верни
  директиву только для следующего шага, получишь результат служебным
  сообщением — передай его в аргументы следующего инструмента без изменений».
- цикл агента ([`llm_bot/agent.py`](../llm_bot/agent.py)): директива →
  выполнение через MCP → служебное сообщение «Результат инструмента …» →
  следующая директива; ограничение `mcp_max_rounds` (по умолчанию 4).

## Контракт вместо нумерации шагов

Изначально первые строки docstring начинались с «Шаг 1/2/3 пайплайна» —
нумерацию убрали: последовательность задают **именованные ссылки на данные**
в контракте каждого инструмента, а не порядковые номера:

- `fetch_rates` обещает «строгий JSON с полем items… передайте items целиком
  в analyze_rates для анализа **или в save_series**, чтобы выгрузить ряд в
  файл» — уже в первой строке видно, что из fetch выходят **две** ветки;
- `analyze_rates` принимает «ряд точек из fetch_rates» и отдаёт агрегаты «в
  save_report»;
- `save_report` принимает «агрегаты из analyze_rates», `save_series` — «вывод
  fetch_rates».

Поэтому агент собирает цепочку под задачу, а не под зашитый сценарий:
полный анализ — три инструмента; «получи курс и выгрузи в файл» — только
`fetch_rates` → `save_series`, без анализа. Нумерация этому мешала бы
(частичная цепочка «Шаг 1 → Шаг 3» выглядела бы для модели противоречиво).
Общая инструкция роутера «строй ЦЕПОЧКУ вызовов… ПО ОДНОМУ» при этом
остаётся — она учит **как** стыковать вызовы, не навязывая **какие**.

Разведены и близкие просьбы: «выгрузи/сохрани курс», даже со словом
«отчёт», но без просьбы про анализ — это одна цель «скачать и сохранить»,
её закрывает `save_series`; `save_report` в контракте явно помечен
«только когда просят именно анализ» (динамика, тренд, min/max). Маппинг
зафиксирован scripted-тестом
`test_agent_builds_a_partial_chain_without_analysis` на живой фразе
«Выгрузи курс доллара за 2025 год и сохрани отчёт» → fetch → save_series
(анализ не вызывается, файл с рядом появляется на диске).

## Три уровня проверки

1. **MCP-транспорт (e2e, без LLM и сети)** — реальный stdio-процесс сервера;
   [`test_server_full_chain_passes_data_between_tools`](../tests/test_mcp_currency_yahoo_server.py)
   скармливает текстовый вывод `fetch_rates` во вход `analyze_rates`, затем в
   `save_report`; плюс контракт первых строк docstring, идемпотентность,
   ошибка на мусорном входе, приём готового объекта и частичная цепочка
   fetch → save_series с проверкой файла на диске.
2. **Детерминированная цепочка на живых данных**
   ([`scripts/mcp_currency_yahoo_demo.py`](../scripts/mcp_currency_yahoo_demo.py),
   лог: [`results/mcp_currency_yahoo_demo.md`](mcp_currency_yahoo_demo.md)) —
   Yahoo, USD за 2025: 24 точки, **113.7222 → 79.4962 (−30.1 %, падение)**,
   min 77.7971 (2025-07-10), среднее 84.5923; три вызова `server__tool` через
   роутер — 3×OK, отчёт сохранён `id=00d50877` («Курс USD за 2025»).
3. **Агент сам строит цепочку** (scripted-LLM,
   [`tests/test_mcp_currency_yahoo_chain.py`](../tests/test_mcp_currency_yahoo_chain.py)):
   - полный сценарий — один промпт «Проанализируй курс доллара за 2025 год и
     сохрани отчёт»: ровно одна директива за раунд, `fetch` → `analyze`
     (байт-в-байт тот же JSON внутри аргументов) → `save`; 4 LLM-запроса,
     отчёт в хранилище;
   - **частичный сценарий** — «Получи курс доллара за 2025 год и выгрузи ряд
     в файл»: `fetch` → `save_series`, `analyze_rates` не вызывается ни разу,
     файл `usd_2025-01-01_2025-12-31.json` появился на диске с 4 точками и
     заголовком;
   - блок инструментов рекламирует цепочки («ЦЕПОЧКУ вызовов», «ПО ОДНОМУ»).

## Находки живого прогона (ограничения моделей/провайдера, не протокола)

1. **API ЦБ РФ выведен из эксплуатации**: старый `XML_dynamic.asp` отдаёт 404.
   Источник заменён на Yahoo Finance chart API — без ключа, один запрос на
   весь период (само название `currency_yahoo` фиксирует источник); офлайн —
   `CURRENCY_FIXTURE`.
2. **Квота провайдера (Groq free tier, 8000 TPM)**: агент `assistant`
   (модель `openai/gpt-oss-120b`) **следует протоколу** и возвращает
   корректные директивы, но обмен из двух раундов (~3.5k токенов — системный
   блок с инструментами, ~4.4k — второй запрос с рядом в служебном сообщении)
   превышает лимит токенов в минуту → 429 после четырёх ретраев. Ряд
   оставлен 24 точки (осознанно); при квоте выше или локальной модели цепочка
   проходит без изменений кода — механика доказана scripted-тестами.
3. **Агент `liquid` несовместим с промпт-протоколом**: модель обучена
   нативному tool-calling и отвечает Hermes-разметкой
   `<|tool_call_start|>[currency__analyze_rates(data='…')]<|tool_call_end|>`
   с битым вложенным JSON, игнорируя даже явную инструкцию «директива —
   обычный текст» (добавлена в `render_tools_block`); при этом она пропускает
   `fetch` и подставляет выдуманный ряд точек. Итог прогона: 0 разобранных
   директив. Для таких моделей нужен транспорт с нативным параметром tools —
   вне рамок проекта (плоские chat-completions без tools).

### Регрессия живого прогона: модель передала `data` готовым объектом

Живой прогон агента `assistant` (курс за 2026 год, реальные данные Yahoo):
цепочка пошла правильно — `fetch_rates` вернул 24 точки, модель вернула
директиву `analyze_rates`, но вложила ряд в `data` **готовым JSON-объектом**,
а не строкой. Аннотация `data: str` на сервере отвергла аргумент
pydantic-ошибкой `string_type` (`Input should be a valid string`). Модель
сама исправилась на следующем раунде — перекодировала объект в JSON-строку,
анализ и сохранение прошли (79.0009 → 84.075, +6.42 %, рост): устойчивость
цикла сработала, но лишний раунд потратил токены и подтолкнул квоту к 429.

Исправление: серверные инструменты принимают payload в обеих формах —
`analyze_rates(data: str | dict | list)` и `save_report(data: str | dict)`;
бэкенд (`extract_series`, `save_report`) уже умел и то, и другое,
строгость была только в схеме MCP-инструментов. Первая строка docstring
теперь говорит об этом явно: «строкой JSON или готовым объектом».

Тест: [`test_server_accepts_data_as_inline_object`](../tests/test_mcp_currency_yahoo_server.py)
воспроизводит живой отказ — `data` передаётся разобранным объектом на обоих
шагах, цепочка проходит без ошибок и без лишнего раунда.

## Конфигурация

Шаблон — [`mcp.example.yaml`](../mcp.example.yaml); локальный `data/mcp.yaml`
(вне репозитория) обновляется вручную — ключ сервера тоже переименован:

```yaml
currency_yahoo:
  command: python
  args: [-m, llm_bot.mcp_servers.currency_yahoo]
  env:
    CURRENCY_REPORTS_DB: data/currency_reports.json
    CURRENCY_SERIES_DIR: data/currency_series
    # CURRENCY_FIXTURE: data/cbr_fixture.json   # офлайн-режим (без сети)
```

## Как пользоваться

```bash
cp mcp.example.yaml data/mcp.yaml            # если ещё не сделано
python -m llm_bot --agent assistant --mcp currency_yahoo \
    "проанализируй курс доллара за 2025 год и сохрани отчёт"
python -m llm_bot --agent assistant --mcp currency_yahoo \
    "получи курс евро за 2025 год и выгрузи ряд в файл"   # без analyze_rates
python scripts/mcp_currency_yahoo_demo.py    # живое демо: цепочка + один промпт агенту
python scripts/mcp_currency_yahoo_demo.py --fixture data/cbr_fixture.json  # без сети
```

Агент по одному промпту сам выбирает нужные инструменты и порядок: каждая
директива возвращается отдельно, результат предыдущего шага приходит
служебным сообщением и передаётся в следующий инструмент; `session.mcp_events`
содержит всю историю вызовов.
