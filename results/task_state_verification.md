## Пример prompt-блока состояния (финальное состояние машины)

```text
Состояние задачи (task state machine):
Этап: validation
Задача: Подготовить отчёт о сравнении двух алгоритмов сортировки
Текущий шаг: сравниваем алгоритмы по критериям
Ожидаемое действие: Собрать данные, проанализировать их и оформить итоговый отчёт
Журнал (последние события):
- execution → validation (план готов — проверяем)
- validation → execution (в отчёте не хватает критериев сравнения)
- execution → validation (правки внесены — снова проверяем)
Ты на этапе ПРОВЕРКИ. Проверь результат по критериям задачи, перечисли дефекты и риски. Ничего нового не добавляй. По итогам: если дефекты есть — предложи /task rework (возврат к выполнению), если всё чисто — команда /task next завершает задачу.
Продолжай работу по состоянию задачи, не требуя повторных объяснений.
```

## Механика «продолжение без повторных объяснений»

1. Задача ставится из диалога (авто-детект, маленький LLM-вызов после хода) или вручную: `/task start <описание>` — этап `planning`.
2. `/task next` ведёт по конвейеру `planning → execution → validation → done`; нелегальные переходы отклоняются таблицей `TRANSITIONS`.
3. `/task pause` — с любого нетерминального этапа; снимок (этап, шаг, ожидаемое действие, журнал) пишется в JSON сессии (`task_state`).
4. После перезапуска новая `Session` восстанавливает снимок и инжектирует его system-сообщением в каждый запрос — достаточно сказать «продолжай».
